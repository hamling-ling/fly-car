# sts3032_bench — STS3032 置き換えのベンチ／テスト一式

fly-car の駆動モーターを FEETECH FM90（開ループ）から FEETECH STS3032
（ST-3032-C001, 6 V 版。12 V 版 C062 と混同しないこと）へ置き換えるための
ベンチ測定とテストプログラム。STS3032 は 12 bit 磁気エンコーダ内蔵で
速度閉ループ（モード 1）を持ち、左右の速度を指令に対して数 % 以内に
揃えられることが採用理由。

## 中身

- `python/sts3032_bench.py` — PC + FE-URT2（USB）でのベンチ測定。
  `--check`（ping／MODE／電圧）、`--rpm 48|16|-16|-48`（Present Speed の
  サンプリングと左右差の表示）。要 `pip install feetech-servo-sdk`。
- `python/sts3032_set_mode.py` — モード 1（速度閉ループ）への設定。
- `python/sts3032_set_id.py` — 2 台目の ID を 1 → 2 に変更し、モード 1 まで
  設定する。**必ず対象の 1 台だけを接続して実行すること**（出荷時は全個体 ID=1）。
- `sketch/sts3032_test_monitor/` — Arduino UNO Q（MCU）から URT-2 の UART
  ヘッダ経由で駆動するテストスケッチ。コンソールは Monitor（RouterBridge）、
  バスは Serial1（D0/D1）。1 文字コマンド p/i/1/T/t/q/r/b/s と、
  `d`＋数字での宛先 ID 切り替え。

## 配線（UNO Q 駆動時）

- URT-2 TX → UNO Q D1、RX → D0（FEETECH 指定どおり同名接続）、
  URT-2 V → UNO Q 5V、GND 共通。レベル切替スイッチは 3.3 V 側。
- サーボ電源 6 V は URT-2 のネジ端子 G／V1 へ。URT-2 の USB と MCU 配線は
  同時に使わない（どちらか一方）。
- ヘッダの V は USB 未接続時に URT 基板の変換回路へ給電する入力で、
  サーボ電源とは別系統。同時に繋ぐのが公式構成。

## 実測結果（2026-11-28、ベンチ計画の項目 1〜4 は合格）

- 項目 1（左右一致 @48 RPM）：定常 ID1 ≈47.6／ID2 ≈48.0 RPM、左右差 0.9%。
- 項目 2（低速 @16 RPM）：定常 ≈15.4 RPM。不感帯なしで立ち上がる
  （FM90 が最も苦手だった領域）。
- 項目 3（負荷耐性）：タイヤなしの軸を強くつまんでも止まらず、46–48 RPM を維持。
- 項目 4（前後対称）：−48 で ≈−47.5／−47.6、−16 で ≈−15.5／−15.6。
  前進と絶対値で 1% 以内の一致。FM90 のような後進専用カーブや不感帯
  シフトは不要で、前後とも同一の指令則でいける。
- UNO Q スケッチ経路も実証済み：ping／情報読み取り／ID 切替／両台の回転。

## 注意（実測で分かったこと）

- 速度指令の単位は steps/s（4096 steps/回転、48 RPM = 3277）。
  Present Speed の読みは 50 steps/s 刻み（48 RPM で ±0.8%）。
- STS3032 に電流フィードバックはない（addr 69 は常時 0）。トルクの代用は
  Present Load（addr 60）だが、無負荷でも約 ±50% を指すデューティ比寄りの
  量なので、相対変化だけを見ること。
- FEETECH の EEPROM 書き込み（MODE／ID）は、書き込み応答が失敗でも
  実際には通っていることがある。成否は電源再投入後の読み戻しで判定する。
- バスが無応答のときは、まずサーボの電圧を正常系（USB 経由）で読むこと。
  給電抜け（USB 給電だけだと約 4.2 V、正常は約 6 V）が最も多い原因だった。
