# ラジコン

Arduino Uno Q の App Lab アプリ。ブラウザに Brio 100 の映像を出し、十字キーで左右の車輪を動かす。車輪のピンとパルスは [motor_test](../motor_test/) で前進と後進を確認したときのまま。

## 動かし方

ボード上の置き場所は `~/ArduinoApps/remote_control`。PC のリポジトリから置くときは、リポジトリ直下で次を実行する。

```bash
scp -r research/remote_control arduino@<ホスト名>.local:~/ArduinoApps/
```

SSH で入って起動する。起動コマンドはシェルに戻る。アプリはそのまま動いている。

```bash
ssh arduino@<ホスト名>.local
arduino-app-cli app start ~/ArduinoApps/remote_control/
```

止めるときは、同じ SSH セッションで次を実行する。

```bash
arduino-app-cli app stop ~/ArduinoApps/remote_control/
```

`No Colon In First Item Of Depfile` と出たら、スケッチのキャッシュが壊れている。消してから起動し直す。

```bash
rm -rf ~/ArduinoApps/remote_control/.cache
arduino-app-cli app start ~/ArduinoApps/remote_control/
```

ページはポート 7000。同じ LAN のブラウザで `http://<ホスト名>.local:7000` を開く。

App Lab でこのディレクトリを開いて Run してもよい。

カメラのつなぎ方は [camera_capture_q](../camera_capture_q/README.md) と同じ。USB-C を PC に刺したデバイスモードではカメラは列挙されない。給電できるハブの先に Brio 100 を置く。

## 操作

| 入力 | 車輪 |
| --- | --- |
| ↑ または W | 前進 |
| ↓ または S | 後退 |
| ← または A | その場で左旋回 |
| → または D | その場で右旋回 |
| 前進と左右を同時 | 曲がる側の車輪を止め、反対側だけ進める |
| キーを離す、スペース、画面の「停止」 | 停止 |

画面の十字も同じ。速度は 0〜255 の整数を直接入れる。既定は 160。数値の欄では十字キーは車を動かさない。上下で数を変え、左右で桁を移動する。傾きは 0.01、切片は 0.1、折れ目と速度は 1 ずつ変わる。欄の外では上下が前進と後退、左右が旋回。WASD は欄にいても車輪を動かす。`motor_test` で回した 255 まで上げられる。正が前進で、表示の右と左は `setMotorSpeed` に渡す値。反時計回りの倍率は、このページには無い。

「折れ線で左を決める」がオンのとき、速度は右の指令になる。直進と後退の左は、その右から折れ線で決める。旋回は曲がる側を止め、動く側は速度のまま送る。その場の回転も、左右に同じ大きさの速度を送る。チェックを外すと左右が同じ速度になる。前進と後退で、折れ目、そこまでの傾き、そのあとの傾き、切片をそれぞれ入れられる。このタブを開き直しても最後の値が残る。初期値は [straight_limits.ipynb](../notebooks/straight_limits.ipynb) の折れ線で、前進の折れ目は右 90、傾きは 0.943 から 0.269、切片は約 −3.10 である。後退の折れ目は右 75、傾きは 1.023 から 0.537、切片は約 1.66 である。測った範囲は前進の右 21〜125、後退の右 36〜100 で、それより外は同じ折れ線を延ばす。左の計算が 0 以下なら 0、255 を超えたら 255 にする。速度の下に、止めたままの直進と後退の指令が出る。カメラの下には同じ折れ線のグラフが出る。横軸が右、縦軸が左で、金が前進、青が後退、破線が左 = 右、点は今の速度である。係数か速度を変えると、グラフも変わる。

キーを押しているあいだ、ページは 0.2 秒ごとに同じ指令を送り直す。ボードは 0.45 秒受信が無いと止める。ページを閉じたとき、別の窓へ移ったときも止める。ブラウザは 1 つにする。

## カメラ

プレビューは 1280×720 の MJPG。`capture.py` で映ったサイズと同じ。640×480 は露出が上がる前に撮るとほぼ黒だった。

`Camera` は fps に 0 を受け付けない。開くときに `STREAM_FPS`（10）をカメラへ書くと、シャッターはその間隔で頭打ちになる。開いた直後に `capture.py` と同じ 3 つをセットする。`auto_exposure=3`、`exposure_dynamic_framerate=1`、`white_balance_automatic=1`。シャッターは部屋の明るさに合わせて最長 250 ms まで伸び、fps はそれに追従して下がる。ページへ出す前に 20 フレーム待ち、ガンマ 0.8 で影を持ち上げる。ガンマだけでは真っ黒は絵にならない。

起動ログの `camera:` 行に、デバイスと 20 フレーム後の平均輝度が出る。

```bash
arduino-app-cli app logs ~/ArduinoApps/remote_control/ --tail 50
```

Python だけ直したときは、スケッチのキャッシュは消さなくてよい。止めてからコピーし、起動し直す。

## 車輪

右がピン D3、左がピン D5。指令 -255〜255 を 1000〜2000 µs にする。1500 µs が停止。左モーターの +/- は逆つなぎなので、正の指令は左右とも 1500 µs より長いパルスにする。右はそのパルスで前進し、左は配線が逆なので同じ側のパルスで前へ回る。`setMotorSpeed` の引数は右、左の順。右旋回はその場で右が負、左が正。前進しながらなら、曲がる側の車輪が止まり、反対側だけ進む。

このアプリは、1500 µs からの幅を指令の絶対値だけで決める。反時計回りだけ広げる倍率は掛けない。動き出しの下限も掛けない。速度 12 や 35 は、下の表で見たままの動きになる。`src/flycar_q` は送信直前に、前進 13 未満と後退 −36 より大きい負を 0 にする。`research/motor_test` のスケッチは同じ µs の式で、下限は掛けない。折れ線は Python が `setMotorSpeed` の前に左の整数を置き換えるだけで、スケッチの式は変えない。

## 2026-10-17 のテーブル

車体は接地させて見た。タイヤは持ち上げて空転させた。前進は左右が同じ。後退は右が先に回り、30〜35 では車体がゆっくり時計回りになる。

| 見方 | 動き出したと扱う | それ未満 | 空転で回り続ける | 空転でカクカクが消える |
| --- | --- | --- | --- | --- |
| 前進・車体 | 13（1525 µs） | 0〜12。9〜12 は進むが、触れると止まる | — | — |
| 前進・左右のタイヤ | — | 7 でカクカクして続かない | 9（1517 µs） | 17（1533 µs） |
| 後退・車体 | 36（1430 µs） | 30〜35 は時計回りにずれ、触れると止まる | — | — |
| 後退・右タイヤ | 車体に合わせる | 25 でピクピク | 27（1448 µs） | 31（1440 µs） |
| 後退・左タイヤ | 車体に合わせる | 34 では止まったままなことが多い | 36（1430 µs） | 42（1418 µs） |

µs は `trunc(n / 255 × 500)` を 1500 に足した値で、スケッチが小数を切り捨てたあとである。後退はその分だけ 1500 より短い。13〜14 はテーブルでは弱い。絨毯では進まない、という見立てのままである。指で止まらなくなる値（前進 17、後退の右 31、左 42）は下限にしていない。後退の左右差（空転で約 9〜11）も、まだ足していない。
